# ai-ui

The OS-level interface: a desk you arrange, not a chat log.

> **Status: built and running — 114 tests, `npm test`. Unproven.** The design is
> [`../doc/04-ai-ui.md`](../doc/04-ai-ui.md); the seam it talks over is
> [ADR-0006](../doc/adr/0006-ai-flows-lives-outside-core.md).
>
> "Built" means the desk exists and does what the document claims: documents,
> agent cubes, the trace face, layout that persists per scope. What has **not**
> happened is the falsification — the stopwatch, a three-day-old flow somebody
> else ran, desk against `web-ui` transcript. Until that runs, the honest claim
> is that it works, not that it helps.

## In one paragraph

A transcript is the right shape for a conversation and the wrong one for work
spanning weeks. The desk is a **spatial, live projection of the state of a
flow** — composed by the system from that state, overridable by the user, and
the override wins from then on.

## Try it without installing anything

[**evolvingagentslabs.github.io/demo**](https://evolvingagentslabs.github.io/demo/)
— the real client with an in-page fake backend, generated by
`scripts/build-demo.ts` from this source. It is not a mock-up: a demo maintained
separately from the product stops being true within a week while continuing to
look right, so if the desk breaks, the demo breaks.

## Run it

Three processes; the [manual](../doc/manual.md) has the whole sequence.

```bash
cd ai-base  && npm ci && node --env-file=.env src/index.ts        # core     :8080
cd ai-flows && node --env-file=../ai-base/.env scripts/serve.ts   # flows    :8097
cd ai-ui    && node scripts/serve.ts                              # the desk :8098
```

`FLOWS_API_URL`, `DESK_PORT` and `FLOWS_SIGNING_SECRET` override the defaults.
With `DATABASE_URL` set the layout survives a restart; without it the desk still
works and **says so in the log** rather than pretending — an arrangement that
silently evaporates is worse than one that was never promised.

## What is here

One package: a layout model, a layout store, a render and a server. It talks to
`ai-flows` over the signed seam and owns nothing but the arrangement.

| | |
| --- | --- |
| `layout.ts` | `propose()`, the `pinned` bit, cubes on documents — **the load-bearing module** |
| `layout-store.ts` | one row per scope, whole layout as JSON; Postgres and in-memory |
| `server.ts` | `GET /` and `/state`, `PUT /layout`, `POST /assign` `/unassign` `/advance` |
| `desk.ts` | the whole page — inline CSS, inline JS, no external requests |
| `trace.ts` | what actually happened: attempts, contribution, observability drift |
| `zoom.ts` | semantic zoom — fifteen attempts become one object, and the fifteen survive |
| `actions.ts` | the menu that reveals itself: proposed actions for *this* flow, each with its cost |
| `projection.ts` | the cache that lets a model write a projection without a render ever spending |
| `memory.ts` | **a drawing of software that does not exist** — see below |
| `flows-http.ts` | the signed client for `ai-flows` |
| `simulate.ts` | `window.fetch` replaced in-page, so the demo is the real client |
| `tour.ts` | Play — the demo driving itself with real events. Demo only; a test asserts the product cannot ship it |

The visual vocabulary — bevels, cubes, the colour per kind and state — is
**not** here. It lives in [`../ai-flows/src/vocabulary.ts`](../ai-flows/src/vocabulary.ts)
because the read-only explorer draws with it too, and a purple cube must not
mean two different things on two surfaces.

## The four properties, and how each is discharged

| | |
| --- | --- |
| **Spatial** | Drag a document; it is still there after a reload, from `ui_desk_layout` keyed by scope. **[ran]** |
| **Live** | The desk re-reads state every five seconds; the agent of a running step is the one thing that animates |
| **Generated** | `propose()` lays documents into a grid and stacks each agent's cube on the flow whose steps name it |
| **Steerable** | Dropping a cube on a document appends a delegation step — the same instruction `compose.ts` writes, asserted byte-for-byte |

The hard part is not the rendering. It is what happens to the arrangement a
person made when the system wants to propose a new one: every placement carries
a `pinned` bit set the moment a human drags it, and `propose()` routes around
pinned things rather than overwriting them. A canvas that gets this wrong throws
away the user's work every time a step finishes — which is exactly when they are
looking at it. **16 tests in `test/layout.test.ts` hold that rule** against the
events that would break it: a flow finishing, appearing, being deleted, and a
cube dropped on a flow whose new step has not run yet.

## What it deliberately does not do

**Reading the desk never spends a model call.** `POST /assign` writes a step and
`POST /advance` runs one; everything else is a read. The desk polls itself, so a
canvas where rendering could trigger work would spend money because somebody left
a tab open. Advancing is a click, with the cost stated on the button's own panel
before it is pressed.

**No build step.** The client is one string of plain JS. This pillar is the one
most at risk of costing a quarter of infrastructure before it has earned one, and
a bundler is the first instalment of that bill. If the stopwatch says the desk
wins, a build step is cheap to add and will have been paid for.

**The memory drawer is a sketch.** `ai-storage` is not built, so `memory.ts` is a
picture of it — cheaper than a document to argue with, and marked as not built
**on the object** rather than in a footnote. `trace.ts` is the opposite: every
field there comes from the flow store.

## Not here yet

- The **stopwatch** above. Everything else is optional until it returns a number.
- Packaging as a **fifth plugin** beside `web-ui`, `admin`, `portal` and `auth`,
  under `ai-base/deploy/layers/evolvingagents/plugins/`. Today it is a standalone
  `node:http` server; the plugin image is the plan in
  [04-ai-ui](../doc/04-ai-ui.md#relationship-to-the-existing-web-ui).
- Multi-pointer drag. One `drag` at a time is a deliberate v1 bound —
  simultaneous multi-user canvas editing is out of scope until the desk is worth
  sharing.
- **Phase 5** of [15 · Generated interaction](../doc/15-generated-interaction.md):
  the gesture that edits the markdown defining the system. Specified, not built —
  it is the one item there where being wrong edits the system rather than a
  record of it.

## Rules

- `ai-ui` **does not fork or replace `web-ui`.** Running both is what makes the
  comparison measurable instead of asserted.
- Signed HTTP to `ai-flows` and to core. **Never import core** (the chassis
  contract). Where the desk needs data core's API does not expose, the fix is a
  route in `ai-flows`, not a special channel into core.
- Auth, identity and scope come from core; the desk renders what the caller's
  scope permits and never widens it.
- The system proposes an arrangement on state change and **never re-arranges
  what the user has touched.**
- The page stays **self-contained** — no external requests, so a broken network
  shows an empty desk rather than an unstyled one.
- Anything drawn in a colour must appear in a legend generated from the
  vocabulary tables, never from a hand-kept list.
